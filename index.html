Pylon

Microsecond core elasticity for Cloud Hypervisor VMs. A per-host arbiter moves physical CPU cores between VMs as their demand changes, through shared memory and a sched_ext scheduler. Part of the Glidex cloud suite.

Quick start Documentation GitHub

Under active development. Arbitration, parking and waking, metering and the sched_ext dispatcher work; cooperative revocation doesn't yet. See Status and roadmap.

git clone https://github.com/CMKL-APEX/pylon.git && cd pylon
cargo build --release -p cloud-hypervisor -p pylond

Features

Elastic vCPUs

VMs boot with all their vCPUs; only the ones with work get a core. The rest are parked and cost nothing.

Per-host arbiter

pylond polls guest demand about every microsecond on a dedicated core, with no locks or allocations in its loop.

Per-VM policy

Minimum and maximum cores and a priority weight per VM, changeable at runtime.

Kernel handoff

The scx_pylon BPF scheduler runs each core's owner, read from a memory-mapped map.

Metering

Core-microseconds, yields and preemptions per VM, over a socket and as Prometheus metrics.

Upstream-friendly

A surgical fork: new crates under pylon/ and one VMM file, with one-line hooks upstream.
