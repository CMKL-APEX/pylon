Pylon

Shared-memory ABI

Every Pylon VM has one 8,192-byte shared page. The VMM, pylond and the guest all map it, and it’s the only channel between the guest and the host on the hot path. Its layout is defined once, in pylon/pylon-abi/src/lib.rs (#![no_std], so a guest kernel can use it too). The design is in spec/01-shared-memory-abi.md.

Rules

  • One writer per cache line, where possible. Each structure is #[repr(C, align(64))], one 64-byte cache line, so that the guest and the host don’t keep stealing the same line from each other. Each vCPU slot is split in half: the lower 32 bytes for the guest side, the upper 32 for the host side.
  • Atomics only. After the VMM initializes the page, every field that changes is an AtomicU8, AtomicU32 or AtomicU64. No reader takes a lock.
  • Fixed size. The page is exactly two 4 KiB pages. Compile-time assertions check every structure’s size and revoke_requested’s offset.

Two limits follow from the types: at most 64 vCPUs per VM, and assigned_pcpu can only name host CPUs 0–254.

Who writes what, today

ABI version 2 gives each field one writer (spec 06 §3), and the field docs in pylon-abi say which:

FieldWriter
stateThe guest, only RUNNING → PARKING for its own vCPU; the VMM, every other transition. Never pylond.
revoke_requestedpylond sets it; the VMM clears it when it parks the vCPU.
yield_count, last_yield_tsc, forced_preempt_countThe VMM, when it parks the vCPU.
assigned_pcpu, revoke_deadline_tscpylond. The VMM initializes assigned_pcpu to PCPU_UNASSIGNED.
park_on_bootThe VMM sets and clears it. pylond reads it: it asks the VMM to park a tagged vCPU (it sets revoke_requested) once guest_heartbeat is non-zero.
host_tid, guest_tsc_offset, park_timer_deadline_tscThe VMM.
TelemetryThe guest (today pylon-guest-agent, which writes nothing else).

Version 2 has the same layout as version 1. The version changed because version-1 guest components broke these rules; a version-1 agent refuses a version-2 page, and the other way round. park_timer_deadline_tsc and guest_tsc_offset were added later in version 2, in bytes that were reserved and zero, and readers treat 0 as “not provided”, so they didn’t need a new version.

Time bases

Every *_tsc field and tsc_khz count host counter ticks: the TSC on x86_64 and the virtual counter CNTVCT_EL0 on aarch64. The names and the layout don’t depend on the architecture.

The guest writes head_wait_tsc and next_timer_tsc with its own counter. Under KVM that differs from the host’s by the vCPU’s offset (a new vCPU’s counter starts near 0). The VMM measures the offset when each vCPU thread starts, by reading the guest’s counter (IA32_TSC on x86_64, KVM_REG_ARM_TIMER_CNT on aarch64) between two host counter reads, and stores it in guest_tsc_offset. PylonSharedPage::guest_to_host_tsc subtracts vCPU 0’s offset, since KVM keeps a VM’s vCPU TSCs in sync. The conversion assumes the guest TSC runs at the host’s rate (no TSC scaling). Every other TSC field is host TSC.

Memory ordering

Writers that publish something another party acts on use Release, and the readers that act on it use Acquire. For example, pylond stores revoke_deadline_tsc and then revoke_requested = 1 with Release, so a reader that sees the flag with Acquire also sees the deadline. Counters and timestamps that are only sampled use Relaxed.

The guest’s side of that contract depends on the guest’s memory model. On x86_64, ordinary loads and stores are already ordered strongly enough for these pairs.

The page in guest memory

The VMM maps the page as a shared memory slot at PYLON_DEFAULT_GPA (0xFEDF_0000), or at --pylon gpa=. On x86_64 that address sits between the IOAPIC and the local APIC, outside the PCI windows. Like a device BAR, the page is not part of the VMM’s guest RAM (GuestMemoryMmap), so the guest’s E820 table, the PVH memory map and ACPI don’t list it. MemoryManager keeps the mapping alive for the VM’s lifetime. A guest maps it through /dev/mem, which CONFIG_STRICT_DEVMEM allows for addresses that aren’t RAM.

Changing the ABI

  1. Change the spec first (spec/01-shared-memory-abi.md), and say who writes the new field.
  2. Use reserved or padding bytes, and keep every structure 64 bytes. The compile-time assertions fail otherwise.
  3. If the change alters a field’s meaning or its writer, bump PYLON_ABI_VERSION. pylond refuses pages with another version, so update the VMM, pylond and guest components together.
  4. Update every reader and writer: vmm/src/pylon.rs, pylond/src/engine.rs and lib.rs, pylon-guest-agent, and the tests that build pages by hand (pylond/tests/e2e_pylon.rs, pylon_bench.rs).
